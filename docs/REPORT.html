1. 프로젝트 개요

1.1 배경

교재 357쪽의 simplesh.c는 fgets()로 한 줄을 입력받고, getargs()로 인자를 나눈 뒤 fork()와 execvp()로 명령을 실행하고 부모가 wait()로 기다리는 구조이다. 쉘의 기본 원리를 보여 주지만 exit, 백그라운드 실행, 인터럽트 처리, 재지향, 파이프, 내장 명령이 없어 실제 사용에는 부족하다.

쉘은 사용자와 운영체제 사이에서 명령을 해석하고 프로세스를 생성하는 프로그램이다. 따라서 쉘을 구현하려면 문자열 파싱, 프로세스 생성, 파일 디스크립터, 시그널, 프로세스 그룹, 대기 상태를 함께 다루어야 한다. 이 프로젝트는 이 요소들을 직접 구현하는 것에 더해, 실행 중인 쉘과 프로세스의 내부 상태를 확인할 수 있는 도구를 같이 제공한다.

1.2 주제

주제는 “시스템 프로그래밍 학습용 투명 쉘”이다. 여기서 투명은 쉘 자신의 동작과 자식 프로세스의 상태를 사용자가 직접 확인할 수 있다는 뜻이다. 명령을 실행하는 기능과, 실행 과정을 보여 주는 기능을 같은 바이너리에 결합했다.

구분 내용
실행 명령 해석, 파이프, 재지향, 백그라운드, 내장 명령
파서 확인 explain: 파이프라인·재지향·연결자 구조 출력
파이프 확인 pipestat: 단계별 바이트, 시간, 종료 코드

ELF/프로세스 확인 dbg: 심볼, 브레이크포인트, 레지스터, 메모리, 백트레이스
프로세스 상태 확인 inspect: /proc status, fd, maps, namespace, process tree
세션 기록 rec/replay: 명령·출력·상태·시간, HTML 내보내기

1.3 목표

  • trace와 dbg로 시스템 호출과 ELF 프로그램 실행을 추적한다.
  • inspect로 /proc 기반 프로세스 상태를 조사한다.
  • rec/replay로 세션을 기록하고 결과를 HTML로 남긴다.
  • 자동 테스트로 기능과 회귀를 검증한다.

2.4 실행 흐름

2.4.1 입력과 파싱

main.c의 find_separator()가 따옴표와 이스케이프를 고려해 최상위 ;와 &를 찾고, 각 세그먼트를 parser.c로 넘긴다. parser.c는 단어와 연산자를 분리하고 작은따옴표(문자 그대로), 큰따옴표($ 확장 허용), 백슬래시를 처리한다. $VAR, ${VAR}, $?, $$, $!, $(...)를 확장하고, 인용되지 않은 *, ?, []는 glob()으로 전개한다.

문법은 명령 목록, 파이프라인, 명령, 재지향으로 나뉜다. &&와 ||는 connector_t로 기록되어 execute_command_list()가 직전 종료 상태에 따라 실행 여부를 결정한다. 2>, 2>>, 2>&1, &>, &>>는 redirect_t에 저장된다.

list     := pipeline ((';' | '&') pipeline)*
pipeline := command ('|' command)*
command  := word+ redirect*

2.4.2 프로세스와 재지향

파이프라인은 명령 수만큼 pipe()와 fork()를 사용한다. 첫 자식이 setpgid(0, 0)로 프로세스 그룹을 만들고 이후 자식과 부모가 같은 pgid에 참여한다. 부모는 tcsetpgrp()로 터미널 전경 그룹을 자식에게 넘기고, 모든 자식의 waitpid() 결과를 수집한 뒤 다시 쉘 그룹으로 복원한다.

재지향은 파이프 연결 뒤에 적용된다. open()/dup2()로 표준 fd를 바꾸고 원래 fd를 닫는다. 2>&1은 stdout을 stderr에 복제하고, &>는 stdout과 stderr를 같은 파일로 보낸다. 내장 명령 중 cd, exit, jobs, wait, export처럼 쉘 상태를 바꾸는 명령은 부모에서 실행하며, 재지향이 있으면 fd를 저장·복원한다.

2.4.3 시그널과 작업 제어

쉘은 SIGINT/SIGQUIT/SIGTERM/SIGHUP 핸들러를 설치한다. 전경 작업 중에는 터미널 전경 그룹이 자식이므로 Ctrl-C는 자식에게 전달되고, 자식은 fork 직후 SIGINT/SIGQUIT/SIGTSTP 등을 기본값으로 복원한다. 백그라운드 작업은 job_t에 등록하고 waitpid(WNOHANG)로 주기적으로 회수한다.

과제 명세의 Ctrl-Z=SIGQUIT을 맞추기 위해 termios의 VQUIT를 0x1A로 설정하고 VSUSP를 비활성화한다. 쉘 종료 시 저장한 termios를 복원한다.

2.4.4 내장 명령

11개 필수 명령은 cmd_ls.c, cmd_fs.c, cmd_text.c에 구현되어 있다. ls는 opendir/readdir/lstat를 사용하고 -a, -l, -R, -h를 지원한다. cp/rm/mv는 재귀 처리와 경로 검사를 포함하고, cat은 -n/-b/-E/-T, grep은 POSIX regex와 -i/-v/-n/-c/-l/-r/-E/-F/-q 등을 지원한다. echo, export, unset, jobs, wait, help, true, false, :는 builtin.c에 있다.

2.4.5 explain

explain은 parse_line()을 실행하되 명령을 실행하지 않고, 파이프라인·명령·재지향·백그라운드·연결자 구조를 출력한다. 예를 들어 cat a.txt | grep hello > out.txt는 두 개의 명령과 stdout 재지향을 가진 파이프라인으로 표시된다. 파서가 입력을 어떻게 해석했는지 확인하는 도구이다.

explain: 1 pipeline(s)

[pipeline 1] foreground (first)
  ├─ cmd: cat a.txt
  └─ cmd: grep hello
       ├─ stdout → out.txt (truncate)

2.4.6 pipestat

pipestat는 각 파이프 단계와 다음 단계 사이에 relay 프로세스를 넣는다. relay는 데이터를 전달하면서 바이트 수를 세고, 부모는 단계별 시작/종료 시각과 종료 코드를 수집한다. 출력은 단계 번호, 명령, 바이트 수, 소요 시간, 상태로 구성된다.

shell> pipestat 'echo hello | cat | wc -c'
6

[1] echo hello: 6 bytes, 0.000s, status 0
[2] cat: 6 bytes, 0.000s, status 0
[3] wc -c: 2 bytes, 0.003s, status 0

2.4.7 trace

trace는 자식에서 PTRACE_TRACEME 후 SIGSTOP으로 멈추고, 부모가 PTRACE_SETOPTIONS와 PTRACE_SYSCALL로 추적을 시작한다. 시스템 호출 진입/종료 정지에서 PTRACE_GETREGS로 orig_rax, 인자 레지스터, rax를 읽는다. 경로 인자는 PTRACE_PEEKDATA로 자식 메모리를 읽어 문자열로 표시한다. -c는 호출 횟수 요약, -f는 fork/vfork/clone 자식 추적, -e는 이름 필터이다. 이름 테이블은 생성된 trace_syscalls.h를 사용한다.

shell> trace -e write /bin/echo hi
hi
write(1, 0x..., 3) = 3

2.4.8 dbg

dbg는 ELF64의 .symtab(없으면 .dynsym)에서 함수 심볼을 읽는다. PIE 실행 파일은 /proc/PID/maps에서 로드 기준 주소를 계산해 심볼 주소에 더한다. break는 대상 주소의 첫 바이트를 0xCC(int3)로 바꾸고, 정지하면 원래 바이트를 복원한 뒤 rip를 1 되돌린다. step/continue는 한 명령을 실행한 뒤 0xCC를 다시 심는다. finish는 프레임의 복귀 주소에 임시 브레이크포인트를 설치한다. bt는 rbp 체인을 따라 반환 주소를 심볼로 바꾸고, SIGSEGV 등에서는 rip와 백트레이스를 자동 출력한다.

shell> dbg ./a.out
(dbg) break main
Breakpoint 1 at 0x401148 (main)
(dbg) run
Breakpoint 1, 0x401148 in main ()
(dbg) regs
rip=0x401148 rsp=0x7fffffffe4d8 rbp=0x7fffffffe580
(dbg) bt
#0  0x401148 in main ()
(dbg) step
Stopped at 0x40114c in main ()
(dbg) continue
v=42
[Inferior exited with status 0]

2.4.9 inspect

inspect는 /proc를 읽어 쉘과 다른 프로세스의 상태를 보여 준다. 기본 출력은 pid/ppid/pgid/sid, uid/gid, cwd, hostname, umask, rlimit, status, fd, maps, namespace이다. -f는 fd, -m은 memory map, -n은 namespace, -j는 jobs, -s는 status, -t는 process tree만 출력한다.

process tree는 /proc/*/stat의 comm, state, ppid를 읽고 루트 PID의 자식을 재귀적으로 따라간다. 예를 들어 백그라운드 sleep을 실행한 직후 inspect -t를 호출하면 쉘 아래에 sleep 프로세스가 표시된다.

shell> sleep 2 & inspect -t; wait
process tree (root=...):
myshell (...) [R]
  sleep (...) [R]

2.4.10 rec/replay

rec는 전경 명령의 stdout/stderr를 relay 프로세스로 실시간 중계하면서 임시 파일에도 기록한다. 명령이 끝나면 명령, stdout, stderr, 종료 코드, 소요 시간을 길이 기반 레코드로 저장한다. 백그라운드(&) 명령은 지연 캡처 경로를 사용한다. replay는 명령을 다시 실행하지 않고 저장된 출력과 상태를 재표시하며, -s로 지연을 조절한다. rec export는 같은 레코드를 단독 HTML 타임라인으로 변환한다. rec start -x는 explain과 trace -c 요약을 추가한다.

shell> rec start lab.rec
recording to lab.rec
shell> echo hello

기능별 파일 분리와 공통 util 사용으로 모듈 간 결합을 줄였다. 외부 라이브러리 없이 libc/POSIX 인터페이스만 사용해 빌드 의존성을 최소화했다.

3.2 안정성

시스템 호출과 라이브러리 호출의 반환값을 검사하고 errno를 포함한 메시지를 출력한다. 백그라운드 작업은 주기적으로 회수하고 종료 시 정리한다. 파이프/재지향 실패 시 fd를 복원하고, 터미널 종료 시 termios를 복구한다. 기능·확장·추적·디버거·녹화·조사 테스트로 회귀를 확인한다.

3.3 생산성

11개 명령은 외부 프로그램 호출 없이 동작한다. explain과 pipestat은 파이프라인 구조와 단계별 비용을, trace와 dbg는 시스템 호출과 ELF 실행을, inspect는 /proc 상태를, rec은 세션 전체를 보여 준다. 실행 결과를 HTML로 남길 수 있어 별도 서버 없이 확인할 수 있다.

3.4 윤리성

rm은 /, ., ..를 거부하고 재귀 삭제는 심볼릭 링크를 따라가지 않는다. 외부 명령은 execvp()로 직접 실행하며 system()/popen()을 사용하지 않는다. MIT 라이선스로 수정과 재배포를 허용한다.

3.5 표준성과 이식성

POSIX/Linux 시스템 콜과 C 라이브러리를 사용한다. Ubuntu 26.04 WSL2와 gcc 15.2에서 빌드·검증했으며, 터미널 제어와 ptrace 기능은 Linux 환경을 전제로 한다.

3.6 신뢰성과 내구성

같은 테스트를 반복 실행해도 동일한 결과가 나오도록 임시 디렉터리와 종료 상태를 사용한다. 263개 자동 테스트와 PTY 시그널 테스트를 통과했고, 오류 반환값과 파일 디스크립터 복원을 검사한다.
